# Tucked Update Spec: v1.1.3 and v1.2.0

- **Date:** 2026-11-23
- **Baseline:** Tucked 1.1.2 (17), live on iOS and macOS (`v1.1.2-build17`)
- **Scope:** Product and behavioral specification only (no code, no implementation plan)
- **Sources:** `TODO.md`, `DECISIONS.md`, and the 2026-11-23 BasicClips competitive recon

## Executive Summary & Release Split

The next two releases are intentionally split into a **fixes, capture polish, and library-health release (`v1.1.3`)** followed by a **pure automation and system-integration release (`v1.2.0`)**.

Neither release changes persisted SwiftData model fields, entitlements, or StoreKit configuration, so **neither requires a CloudKit Production schema deploy**.

| Cycle | Version | Theme | Highlights | CloudKit Schema Deploy |
|---|---|---|---|---|
| **Cycle 1** | **v1.1.3** | Fixes, Capture Polish & Library Health | `F20` image pan, `F22` URL drop fixes, capture-time "Already tucked" notice, clipboard URL assist, iOS Home Screen Quick Actions, Settings "We Also Make", device-observed iCloud sync timestamps, manual "Check for Broken Links" sweep | None |
| **Cycle 2** | **v1.2.0** | Siri, Shortcuts & Spotlight | App Intents in the "show without opening" model (`openAppWhenRun = false`), rich typed entities, inline SwiftUI result snippets, Untuck rediscovery intents, curated App Shortcuts, CoreSpotlight indexing | None |
| **Deferred** | **v1.3+** | Schema-Bearing Work & Big Bets | `F1` permanent clone-pair fix, `pageDescription` / `og:description`, image-capable backup, JPEG/HEIC photo encoding, Visual Tuck (OCR), etc. | Yes (batched once) |

### Standing Product Invariants (Both Cycles)
- Local-first SwiftData store in the shared App Group (`group.com.loweffortapps.BookmarkCollections`) remains the source of truth; network, metadata, and CloudKit never block saving or browsing.
- Single-collection membership (`0..1` `BookmarkCollection`) plus an independent Favorite Boolean. No tags, no nested folders, no custom accounts, no analytics, no third-party dependencies.
- Normalized URL identity remains authoritative: saving an existing active link updates it; saving a recently deleted link restores it.
- All user-initiated mutations flow through `BookmarkRepository` and `CollectionRepository` and honor the 10-item free limit when `Tucked for Life` is locked.
- System SwiftUI controls, semantic colors, light/dark appearance, VoiceOver, Dynamic Type, and native macOS commands apply across all new surfaces.

## Cycle 1 — v1.1.3: Fixes, Capture Polish & Library Health

A cross-platform maintenance and everyday-ergonomics update that clears remaining non-schema backlog fixes, ships Settings/portfolio updates, adds visible iCloud sync activity and manual link health checks, and removes friction from daily link capture.

### 1. Backlog Fixes & Verification

#### 1.1 Image Viewer Panning While Zoomed (`F20`)
- When viewing a saved image at magnification `> 1×`, dragging pans smoothly around the image on iPhone, iPad, and Mac.
- Pan offset is clamped to the scaled image bounds within the viewport so the image cannot be dragged off-screen or leave empty dead space beyond its edges.
- Returning zoom to `1×` (via pinch-out or double-tap reset) smoothly re-centers the pan offset to zero.
- Preserves the single-decode performance behavior shipped in `1.1.1` (no per-frame image re-decoding during pinch or drag).

#### 1.2 URL Drag-and-Drop Reliability (`F22`)
- **Empty library drop:** Dragging one or more URLs onto an empty library (including an empty All Items or empty Collection view) saves them rather than requiring an existing grid of cards.
- **Respect current collection:** Dropping URLs while viewing a specific `BookmarkCollection` assigns newly saved links to that collection. Existing active links retain their existing collection and Favorite state per the `1.1.1` preservation rule.
- **Fault-tolerant batch handling:** Dropping a batch containing one or more invalid or unsupported URLs (e.g., `mailto:`, malformed strings) skips the invalid entries and continues saving the valid HTTP/HTTPS links.
- **Free-limit & result feedback:** If a drop hits the free limit partway through, keep the links already saved and present the same summary/Unlock pattern used by text import (`1.1.1`).
- **Boundary:** Covers URL drops only; image drag-and-drop remains in Backlog.

#### 1.3 Paywall Verification Under Test Launch Arguments
- Verify the `-free-limit 0` paywall state against the real `Tucked.storekit` configuration (rather than test launch overrides alone). Fix only if a genuine StoreKit defect reproduces; otherwise close the verification item.

### 2. Capture Awareness & Low-Friction Entry

#### 2.1 Capture-Time "Already Tucked" Notice
Tucked’s normalized-URL upsert is cleaner than warn-and-duplicate, but today it happens silently—users never know whether a save created a new item, updated an existing one, or restored a deleted one.

- **In-app Add Link (`AddBookmarkView`):**
  - As the user enters or pastes a valid URL, check normalized-URL matches in the local store.
  - **Active match:** Show a quiet inline notice in the form: *"Already tucked · saved [relative date]"* (appending *"in [Collection]"* if filed). Include a **View** action that dismisses Add Link and navigates to/focuses the existing item in the library.
  - **Recently Deleted match:** Show *"In Recently Deleted · saving will restore it."*
  - **Save behavior unchanged:** Tapping Save still updates the active item (applying the form’s chosen Collection/Favorite) or restores the deleted item, never creating a duplicate.
- **iOS / iPadOS Share Sheet (`ShareCaptureView`):**
  - Leverage the existing `sharedLinkMatch(url:)` lookup to show the same concise inline notice (*"Already tucked · saved [relative date]"* or *"In Recently Deleted · saving will restore it"*) alongside the pre-populated Collection and Favorite controls.
  - **No "View" button in the iOS Share Extension:** Opening the containing app from an iOS Share Extension is unreliable and intentionally avoided (`DECISIONS.md`, 2026-11-02).
- **macOS Share Extension:** Retains immediate, capture-first Quick Save with no added dialog.

#### 2.2 Clipboard URL Assist
- **In-app Add Link (`AddBookmarkView`):**
  - When opened empty and the system clipboard holds a valid HTTP/HTTPS web URL, pre-fill the URL field (or provide an immediate one-tap paste fill) so saving a copied link takes one tap or Return.
  - **iOS paste-permission ergonomics:** Before reading the clipboard string on iOS/iPadOS, check pasteboard URL pattern availability (e.g., probable web URL detection) so opening Add Link with plain text, images, or an empty clipboard **never** triggers the system *"Tucked would like to paste from…"* permission banner.
  - On macOS, check `NSPasteboard` directly for a valid web URL without prompting.
  - When pre-filled, the URL field stays selected/focused and the "Already tucked" check runs immediately so the user sees duplicate status right away.
- **Mac Menu Bar Helper (`MenuBarContent`):**
  - Add a **"Save Link from Clipboard"** action (or quick-capture entry that reads a valid clipboard URL and saves/opens Add Link pre-filled), respecting the active-sheet guard (`F14`) and the free-limit paywall.
- **Scope boundary:** Applies to **web URLs only**. Clipboard *snippet* capture remains out of scope (`TODO.md`).

#### 2.3 iOS / iPadOS Home Screen Quick Actions
Add native app-icon long-press quick actions on iPhone and iPad:
1. **Add Link** — opens the Add Link sheet.
2. **Save from Clipboard** — if the clipboard holds a valid web URL, saves or opens Add Link pre-filled; if not, opens Add Link cleanly with focus in the URL field.
3. **New Snippet** — opens the Snippet editor.
4. **Search** — opens the library and focuses the search bar.

All four actions must route reliably from both cold launch and warm resume, and must respect open sheets/paywall state without discarding unsaved drafts.

### 3. Settings & Library Health

#### 3.1 Settings: "We Also Make" Section
- Add a **"We Also Make"** section in `SettingsView` mirroring the shared `AboutSectionView` pattern in Offshoots, Weather in Words, Task(ed), and EveryPaw:
  - Identical row layout, light and dark app icon artwork, and App Store links.
  - Lists the other live Low Effort Apps and **excludes Tucked itself**.
  - Verify every App Store ID against live listings before release (specifically use Weather in Words ID `6806063498`, not the dead `6760272161`).
- Must adapt cleanly to light/dark mode, macOS grouped form styling, and iOS accessibility text sizes.

#### 3.2 Visible Device-Observed iCloud Sync Timestamps
Amends the 2026-07-18 *Honest sync health* decision per explicit product direction to expose sync timing while keeping the reporting strictly truthful:

- **What Settings → iCloud displays:**
  - Existing iCloud account availability status (`available`, `noAccount`, `restricted`, `temporarilyUnavailable`, or error).
  - **Device-observed sync activity timestamps** derived from real CloudKit mirroring events (e.g., *"Last iCloud push"* and *"Last iCloud pull"*, formatted as relative/short date-time, or *"Not yet observed this session"* / *"Waiting for iCloud…"* before an event occurs).
  - Keep the honest local-first explanation clarifying that these reflect activity observed on **this device** and that saves are always durable locally first (never claiming global multi-device completion).
- **Technical precondition:** Verify during implementation that SwiftData’s underlying Core Data/CloudKit stack delivers `NSPersistentCloudKitContainer.eventChangedNotification` import/export events reliably in Tucked’s container on both iOS and macOS, and persist the last observed push/pull timestamps locally in user defaults so they survive app relaunches.

#### 3.3 Manual Dead-Link Check ("Check for Broken Links")
An opt-in, user-initiated maintenance tool that complements Untuck/Forgotten without adding background network traffic or a persisted CloudKit field.

- **Entry point:** Settings → Library Data (under a clear Maintenance/Library Health action): **"Check for Broken Links"**.
- **Execution behavior:**
  - Checks active `.link` bookmarks only (skips images, snippets, and Recently Deleted items).
  - Runs on demand only—never automatically on launch or when opening links.
  - Uses bounded concurrency, per-request timeouts, and a live cancellable progress UI (*"Checking 14 of 82 links…"*).
  - Issues lightweight `HEAD` requests with an automatic `GET` fallback when a server responds with `405 Method Not Allowed` or `501 Not Implemented` (and follows standard HTTP redirects).
- **Robots-tolerant classification (minimize false positives):**
  - **Flagged as likely broken:** HTTP `404 Not Found`, `410 Gone`, DNS failure (`NXDOMAIN` / host not found), or invalid/unreachable host.
  - **Given the benefit of the doubt (not flagged as dead):** HTTP `401`, `403`, `429`, `5xx` transient errors, bot/anti-scrape challenges, TLS/captive-portal interruptions, or device offline state (if offline, inform the user clearly instead of flagging the whole library).
- **Ephemeral review sheet (zero schema change):**
  - If no links are flagged, confirm *"All checked links look reachable"* (noting how many were checked and skipped/uncertain if applicable).
  - If broken links are found, list each with its title, domain, and plain-language reason (e.g., *"Page not found (404)"*, *"Server not found"*), plus per-item actions:
    - **Open in Browser** (let the user verify manually before removing)
    - **Move to Recently Deleted** (soft-delete; recoverable for 30 days)
  - Provide a **Move All to Recently Deleted** bulk action guarded by a confirmation dialog.
  - Results are ephemeral to the sweep session and do not add a persisted field to `Bookmark`.

### Cycle 1 Acceptance Criteria
- Zoomed image panning works smoothly with edge clamping and clean `1×` re-centering on iPhone, iPad, and Mac.
- Dragging valid, invalid, and mixed URL batches onto an empty library and onto a specific Collection behaves per `F22` without losing existing organization.
- Entering or sharing an already-tucked URL shows the inline notice and preserves upsert/restore semantics without creating duplicates; **View** jumps to the item from `AddBookmarkView`.
- Opening `AddBookmarkView` on iOS with non-URL text on the clipboard does **not** trigger a system paste prompt; with a URL on the clipboard, saving requires minimal taps.

## Cycle 2 — v1.2.0: Siri, Shortcuts & Spotlight

A focused headline minor release introducing first-class Apple system integration across iOS, iPadOS, and macOS. Designed around the **BasicClips "show without opening" App Intents architecture**, tailored strictly to Tucked’s cleaner library model.

### 1. Core App Intents Architecture ("Show Without Opening")

1. **No-open by default (`openAppWhenRun = false`):**
   - Every read, search, rediscovery, and capture/organization intent runs in the background without pulling the user out of their current app, Siri overlay, or Shortcut flow.
   - Only explicit navigation intents (`Open Collection`, `Open Bookmark`) bring Tucked to the foreground.
2. **Rich, composable App Entities:**
   - Bookmarks and Collections are modeled as typed entities with structured properties and queries—not raw strings—so Shortcuts users can filter, branch, inspect fields, and pass bookmarks to other apps (Safari, Messages, Notes, Mail) as real URLs or text.
3. **Inline SwiftUI Result Snippets & Natural Dialog:**
   - Read, rediscovery, and write intents return both a spoken/printed `IntentDialog` and a compact, theme-aware SwiftUI result snippet view (matching Tucked’s calm visual identity: preview/kind glyph, title, domain/snippet excerpt, collection, favorite star) rendered directly inside Siri and Shortcuts.
4. **Siri AI / Apple Intelligence Readiness from Day One:**
   - Every intent, entity, and parameter carries complete natural-language titles, descriptions, and readable parameter summaries so actions work cleanly in Shortcuts today and are ready for App Intents Siri / on-screen awareness without a rewrite (`TODO.md`).
5. **Single Persistence & Paywall Truth:**
   - Background write intents execute against the shared App Group SwiftData store via `BookmarkRepository` / `CollectionRepository`.
   - Normalized URL deduplication, restore-from-deleted, and the 10-item free cap apply identically to in-app saves; hitting the free limit returns a clear, non-crashing dialog telling the user to unlock Tucked for Life in Tucked.

---

### 2. App Entities & Queries

#### `BookmarkAppEntity`
- **Conforms to:** `AppEntity`, `IndexedEntity` (Spotlight), and URL/text `TransferRepresentation` so bookmarks pass cleanly to other apps as links (`.link`) or text (`.text`).
- **Properties:**
  - `id` (`UUID`)
  - `title` (`String`, falling back to domain or snippet first line)
  - `url` (`URL?`, populated for `.link` and `.text` items with a source URL)
  - `domain` (`String`)
  - `kind` (`BookmarkKindAppEnum`: Link, Image, Snippet)
  - `collection` (`CollectionAppEntity?`)
  - `isFavorite` (`Bool`)
  - `createdAt` (`Date`)
  - `modifiedAt` (`Date`)
  - `lastOpenedAt` (`Date?`)
  - `snippetBody` (`String?`, populated for `.text`)
- **Representation:** Thumbnail/preview image (cached/downsampled) or kind SF Symbol + title + domain/collection subtitle.
- **Query (`EntityQuery` / `EntityStringQuery` / `EntityPropertyQuery`):**
  - Lookup by ID (active bookmarks only; excludes Recently Deleted).
  - Full-text string search matching Tucked’s library search semantics (title, domain, URL, snippet body, collection name).
  - Structured property filtering and sorting (`kind`, `collection`, `isFavorite`, `createdAt`, `lastOpenedAt`, `title`).

#### `CollectionAppEntity`
- **Properties:** `id`, `name`, `itemCount` (active count), `createdAt`.
- **Query:** Lists all collections in `sortPosition` order and matches by name.

#### `LibraryDestinationAppEnum`
- Built-in views: `All Items`, `Favorites`, `Links`, `Images`, `Snippets`, `Forgotten`, `Recently Deleted`.

### 3. Intent Catalog

#### A. Capture & Organization Intents (`openAppWhenRun = false`)
- **Save Link**
  - *Inputs:* `url` (optional—accepts full URL or schemeless web address like `example.com`; falls back to clipboard URL when omitted/configured), `collection` (optional `CollectionAppEntity`), `isFavorite` (Bool, default `false`).
  - *Behavior:* Saves via `BookmarkRepository` (preserving organization if updating an existing link when collection/favorite are unspecified, or applying explicit inputs). Triggers normal background metadata eligibility when the app next runs.
  - *Output:* Returns `BookmarkAppEntity` + dialog distinguishing **Saved**, **Already tucked (updated)**, or **Restored from Recently Deleted** + compact card snippet.
- **Save Snippet**
  - *Inputs:* `text` (required non-empty String), `title` (optional), `sourceURL` (optional URL), `collection` (optional), `isFavorite` (Bool, default `false`).
  - *Output:* Returns `BookmarkAppEntity` + confirmation dialog + snippet card view.
- **Set Favorite**
  - *Inputs:* `bookmark` (`BookmarkAppEntity`), `isFavorite` (`Bool`).
  - *Output:* Returns updated `BookmarkAppEntity` + confirmation dialog.
- **Move Bookmark to Collection**
  - *Inputs:* `bookmark` (`BookmarkAppEntity`), `collection` (`CollectionAppEntity?`; `nil` removes from collection).
  - *Output:* Returns updated `BookmarkAppEntity` + confirmation dialog.

#### B. Find & Browse Intents (`openAppWhenRun = false`)
- **Find Bookmarks**
  - *Inputs:* `query` (optional String), `kind` (optional Link/Image/Snippet), `collection` (optional), `favoritesOnly` (Bool, default `false`), `sort` (Date Added, Date Modified, Last Opened, Title), `limit` (Int, default `10`).
  - *Output:* `[BookmarkAppEntity]` + count dialog + compact list snippet (top matches).
- **Recent Bookmarks**
  - *Inputs:* `kind` (optional), `limit` (Int, default `5`).
  - *Output:* `[BookmarkAppEntity]` ordered newest-first + compact list snippet.
- **Show Favorites**
  - *Inputs:* `limit` (Int, default `5`).
  - *Output:* Favorited `[BookmarkAppEntity]` + compact list snippet.

#### C. Rediscovery / Untuck Intents (`openAppWhenRun = false`)
- **Show Forgotten**
  - *Inputs:* `limit` (Int, default `5`).
  - *Behavior:* Applies `UntuckRules.isForgotten` (active items never opened and older than 30 days).
  - *Output:* `[BookmarkAppEntity]` + dialog + inline list snippet (or friendly empty dialog if nothing is forgotten).
- **Surprise Me**
  - *Inputs:* `collection` (optional), `kind` (optional).
  - *Behavior:* Selects one random active item matching the scope.
  - *Output:* `BookmarkAppEntity` + single-item card snippet so users can inspect it in Siri or chain into Safari/Open URL in Shortcuts without forcing Tucked open.
- **On This Day**
  - *Inputs:* `limit` (Int, default `5`).
  - *Behavior:* Finds active items whose `createdAt` matches today’s calendar month and day from prior years (excluding items saved earlier today).
  - *Output:* `[BookmarkAppEntity]` + dialog + inline list snippet (or clean *"Nothing tucked on this day in earlier years"* dialog).

#### D. Navigation Intents (`openAppWhenRun = true`)
- **Open Collection**
  - *Inputs:* Either a `CollectionAppEntity` or a built-in `LibraryDestinationAppEnum`.
  - *Behavior:* Opens/raises Tucked directly to that destination in the library on iPhone, iPad, and Mac.
- **Open Bookmark**
  - *Inputs:* `bookmark` (`BookmarkAppEntity`).
  - *Behavior:* Opens the item (launching the URL for links, opening the image viewer for images, or opening/focusing the snippet in Tucked) and updates `lastOpenedAt` without bumping `modifiedAt`.

### 4. App Shortcuts (`AppShortcutsProvider`)
Register a concise, conflict-free set of 8 default Siri phrases (staying well within Apple’s discoverability budget):
1. *"Save a link in Tucked"* → **Save Link**
2. *"Save a snippet in Tucked"* → **Save Snippet**
3. *"Find bookmarks in Tucked"* → **Find Bookmarks**
4. *"Show my recent bookmarks in Tucked"* → **Recent Bookmarks**
5. *"Show my favorites in Tucked"* → **Show Favorites**
6. *"Show forgotten bookmarks in Tucked"* → **Show Forgotten**
7. *"Surprise me in Tucked"* → **Surprise Me**
8. *"On this day in Tucked"* → **On This Day**

### 5. CoreSpotlight Indexing
- Active bookmarks (`link`, `image`, `text`) are indexed in CoreSpotlight via `IndexedEntity` / Spotlight attributes:
  - Searchable text: title, domain, URL host/path, snippet body, and collection name.
  - Lightweight thumbnail data where already cached locally (never triggers network fetches during indexing).
- **Lifecycle sync:**
  - Creating, editing, restoring, or importing active items updates their Spotlight entry.
  - Soft-deleting or permanently deleting an item removes it from Spotlight immediately.
  - Renaming or deleting a collection refreshes affected items’ searchable metadata.
- **Deep-link launch:** Selecting a Tucked result in iOS/iPadOS/macOS Spotlight opens Tucked directly to that bookmark (same route as `Open Bookmark`).

### Cycle 2 Acceptance Criteria
- Every no-open intent (`Save Link`, `Save Snippet`, `Set Favorite`, `Move to Collection`, `Find Bookmarks`, `Recent Bookmarks`, `Show Favorites`, `Show Forgotten`, `Surprise Me`, `On This Day`) executes in Shortcuts on iOS and macOS **without launching Tucked** and renders a readable inline snippet + dialog.
- `BookmarkAppEntity` outputs chain cleanly into standard Shortcuts actions (e.g., *Open URLs*, *Copy to Clipboard*, *Share*, *Filter*) on iOS and macOS.
- `Save Link` and `Save Snippet` enforce normalized-URL deduplication, restore-from-deleted, and the 10-item free limit identically to in-app saves.
- `Open Collection` and `Open Bookmark` route to the exact target from both cold launch and running states on iPhone, iPad, and Mac.
- Active bookmarks appear in system Spotlight search and disappear from Spotlight when moved to Recently Deleted.
- Zero changes to persisted SwiftData schema or CloudKit Production schema.
