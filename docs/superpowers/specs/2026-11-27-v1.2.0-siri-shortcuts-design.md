# Tucked v1.2.0 — Siri, Shortcuts & Spotlight: Engineering Design

- **Date:** 2026-11-27
- **Status:** Draft for Geoff's approval
- **Product scope:** [v1.1.3 and v1.2.0 spec, Cycle 2](2026-11-23-v1.1.3-and-v1.2.0-spec.md#cycle-2--v120-siri-shortcuts--spotlight). That spec owns *what* ships (intent catalog, entity fields, phrases, acceptance criteria). This doc owns *how*, and records where the how changes the spec.
- **Baseline:** v1.1.3 (18) submitted to App Review on iOS and macOS. Work starts on a branch from `main` after v1.1.3 is merged there (it is: `f9839f5`).

## Intent

v1.2.0 is the system-integration release: one product story, "Tucked works from Siri, Shortcuts, and Spotlight without opening the app." No new in-app features, no schema change. Success means a Shortcuts user can save, find, and rediscover bookmarks from any app, and chain the results into other actions as real URLs or text.

## Goals

- Ship the full Cycle 2 catalog: 12 intents, `BookmarkAppEntity`, `CollectionAppEntity`, `LibraryDestinationAppEnum`, static result snippets, 8 App Shortcuts phrases, CoreSpotlight indexing.
- Same save rules as the app: normalized-URL dedupe, restore from Recently Deleted, 10-item free limit.
- Works on every OS Tucked supports today.

## Non-goals

- Interactive snippets (`SnippetIntent`, buttons inside the card).
- Apple Intelligence schema adoption (`@AppIntent(schema:)`), Visual Intelligence, on-screen entity annotation, `RelevantEntities`, `SyncableEntity`. All are later, opt-in work. Natural-language titles and descriptions on every intent still ship (spec §1.4), so later adoption needs no rewrite.
- Widgets and Control Center controls.
- Any in-app UI beyond the deep-link route.

## Anti-goals (a failure even if it works)

- Running a no-open intent brings Tucked's window forward, or (on Mac) leaves Tucked showing in the Dock.
- An intent save bypasses the free limit or creates a duplicate the app would have merged.
- A persisted SwiftData model change or a CloudKit Production deploy.
- The Share Extension build breaks because shared files changed.

## Constraints

- **Deployment floor stays iOS 18.0 / macOS 15.0** (Geoff, 2026-11-27). Consequences:
  - Execution mode: `supportedModes` / `IntentModes` is iOS 26 / macOS 26. On older OS versions use `openAppWhenRun`, which Apple deprecated in 26. Gate with `@available` / `if #available`, following `references/execution-modes.md` in the `app-intents-whats-new-27` skill. No-open intents rely on the background default. Only `Open Bookmark` and `Open Collection` declare foreground.
  - Snippets: static `.result(dialog:view:)` everywhere (iOS 16+). One code path.
  - Spotlight: `IndexedEntity` + `indexAppEntities` / `deleteAppEntities` (iOS 18 baseline). The iOS 26 property-to-attribute mapping and the iOS 27 `IndexedEntityQuery` reindex hook are gated extras, used only if cheap.
  - Intent tests: `AppIntentsTesting` needs iOS 27. It runs on the iOS 27.2 simulator; it is not a reason to raise the floor.
- **One persistence path.** Intents use `BookmarkRepository` / `CollectionRepository` on the main actor with `PurchaseAccess.isUnlocked` and `PaywallConfiguration.isEnforced`, exactly as the app does. Use the same App Group `ModelContainer` the app uses, made once per process. Never build a second container per intent run.
- **Entity IDs are a public contract.** `BookmarkAppEntity.id` = `Bookmark.id` (UUID). `CollectionAppEntity.id` = `BookmarkCollection.id`. `AppEnum` raw values and phrase text are frozen once shipped.
- **Share Extension untouched.** Intent code lives only in the app target. None of the nine shared files gets intent-only API.

## Approaches considered

| Approach | Trade-off | Outcome |
|---|---|---|
| **A. Intents in the main app target** | Simplest: direct repository and container access, no new target, Open intents and Spotlight share the UI process. Cost: each run starts the full app process in the background; on Mac the app may appear in the Dock. | **Chosen** (Geoff, 2026-11-27) |
| B. Separate App Intents extension target | Lighter, faster, no Dock risk. Cost: a third target that must compile the shared files plus entities; Open intents still need the app. | Fallback if stop 1 shows the Mac Dock problem. The entity and query code moves over unchanged. |
| C. Shared framework linked by app and extension | Most flexible. Large refactor with no user value this release. | Rejected |

## Decided how

1. **Target:** main app target, under `BookmarkCollections/Intents/` (new folder; add a line to `README.md`).
2. **Mac background check is the first task of stop 1.** Build one read intent, run it from Shortcuts on macOS with Tucked quit, and observe the Dock and windows. If Tucked surfaces, stop and bring it to Geoff before building more (likely switch to approach B).
3. **Routing:** `Open Bookmark` (images, snippets), `Open Collection`, and Spotlight taps go through one in-app route. Extend the existing `MenuBarRouter` request pattern (pending request + generation, dropped when blocked by a draft, the paywall, or a drop summary, per DECISIONS 2026-11-10). No URL scheme needed.
4. **`Open Bookmark` by kind:** link → open the URL in the default browser (see item 11), mark opened; image → Tucked image viewer; snippet → snippet in Tucked. `markOpened` must not bump `modifiedAt` (it already does not).
5. **Free limit in intents:** catch `LimitError.limitReached` and return a dialog: you've reached the free limit; unlock Tucked for Life in Tucked. No crash, no paywall presented from the background.
6. **Read intents are free for everyone.** The limit only affects creation, same as in the app.
7. **Snippet view:** one compact card and one compact list (top N rows) in system styles and semantic colors. Kind SF Symbol, or the cached preview if it is already on disk. Never fetch from the network during an intent run or indexing.
8. **Shared container** (from code): the container is a private property made in `BookmarkCollectionsApp.init`. Move it to one static the app and the intents both use. `PurchaseAccess` already reads cached App Group defaults, so intents see the same unlock state as the Share Extension without loading StoreKit.
9. **Save Link `isFavorite` is optional** (Claude's call). `nil` keeps the current value on an update. A set value changes only that field, and the same is true for `collection`. This needs a per-field preserve option in `BookmarkRepository.saveLink`. That file is shared with the Share Extension, so build both schemes.
10. **Spotlight freshness** (Claude's call). The Share Extension and iCloud sync write outside the app's repository calls, so per-call updates are not enough. Reindex all active items on launch and on return to foreground. Also reindex after a remote CloudKit import, using the events `SyncHealthMonitor` already observes. A Spotlight tap on a bookmark that no longer exists opens All Items.
11. **Open Bookmark for links** (Claude's call). Run in the background and hand the URL on through `OpenURLIntent`, so the browser opens and Tucked's window does not come forward. Images and snippets open Tucked in the foreground.
12. **Blocked route** (Claude's call). When an unsaved draft, the paywall, or a drop summary blocks the route, Tucked still comes forward and the user sees the blocker. The intent returns a dialog that says Tucked could not go to the item. It does not report success.
13. **Save Link with no URL** (Geoff, 2026-11-27): Siri asks for the URL (the parameter requests a value). No clipboard fallback. iOS gives no clipboard to an app in the background.
14. **Spotlight tap** (Geoff, 2026-11-27): keep spec §5. Tucked opens with that bookmark selected (the existing `focusBookmark` path), for every kind, links included. A Spotlight tap does not open the browser.
15. **Order of stops** (each is buildable, testable, and reviewable on its own):
   1. Entities and queries; Find Bookmarks, Recent Bookmarks, Show Favorites; Mac background check.
   2. Save Link, Save Snippet, Set Favorite, Move Bookmark to Collection.
   3. Show Forgotten, Surprise Me, On This Day.
   4. Open Bookmark, Open Collection, and the route.
   5. 8 App Shortcuts phrases; Spotlight indexing and lifecycle sync; Spotlight tap → stop 4 route.

## Changes to the product spec

- Spec §1.1 says `openAppWhenRun = false`. Replace that with "background by default; `supportedModes` on iOS/macOS 26+, `openAppWhenRun` gated below." Behavior is unchanged.
- Spec §5 deep-link launch reuses the in-app router, not a URL scheme.
- Spec §3A Save Link: drop the clipboard fallback. Siri asks for the URL.
- Spec §3D Open Bookmark for links: opens the browser through `OpenURLIntent`, and Tucked stays in the background.

## Left to the builder

- Exact file split inside `Intents/`.
- Query implementation (`EntityStringQuery` / `EntityPropertyQuery`) as long as string search matches the library search semantics (`LibraryDestination.searchQuery`) and lookups skip Recently Deleted.
- Dialog wording, within the spec's three save outcomes (Saved / Already tucked (updated) / Restored).
- Whether the gated iOS 26/27 Spotlight extras are worth their lines.
- Test layout: repository-level unit tests in `BookmarkCollectionsTests` for intent logic; `AppIntentsTesting` on the iOS 27.2 simulator where it adds coverage.

## Verification

- Both schemes build (`BookmarkCollections`, `BookmarkShareExtension`) after every stop.
- Focused unit tests per stop; full suite before merge to `main`.
- Simulator check of each intent in Shortcuts on the newest iOS runtime; Mac check on macOS 27.2.
- Not verifiable here: Siri voice phrases on a physical device and macOS 15 / iOS 18 behavior (no runtimes on either Mac). Geoff runs those on device during testing.
